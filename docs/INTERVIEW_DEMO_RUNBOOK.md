# 面试演示运行手册

这份手册用于在面试前 5 分钟确认 Demo 可用，并提供一条不依赖临场发挥的演示路径。

## 1. 演示前检查

```bash
bash ./test.sh
```

生产环境示例：

```bash
BASE_URL=http://127.0.0.1:8000 \
FRONTEND_URL=http://127.0.0.1:5173 \
bash ./test.sh
```

默认检查只访问健康检查、能力列表和前端首页，不会调用 LLM，也不会产生模型费用。确认基础链路正常后，如需验证一次真实回答，再显式执行：

```bash
RUN_LLM=1 bash ./test.sh
```

## 2. 推荐演示路径

1. 打开前端首页，先展示系统健康状态和可用能力。
2. 进入“智能对话”，使用固定问题：

   > 分析最近 24 小时新加坡区域的网络延迟，给出 P50、P95、P99，并说明可能的异常原因。

3. 展开工具调用和执行轨迹，说明自然语言问题如何经过路由、规划、数据查询、证据汇总和答案生成。
4. 切换到可视化结果，展示趋势图、分位数和筛选维度。
5. 最后说明：当数据源或模型不可用时，系统应返回明确的失败原因和已完成步骤，而不是编造结论。

## 3. 面试演示防翻车原则

- 先运行冒烟检查，再打开页面；不要现场首次构建镜像或安装依赖。
- 先展示固定问题，确认主链路成功后再接受面试官的自由提问。
- 不向面试官展示 API Key、数据库密码、内部管理端口或服务器终端。
- 如果外部模型暂时不可用，展示工具执行轨迹、健康状态和已有可视化页面，并说明模型依赖边界。
- 所有回答都应区分“观测到的证据”和“基于证据的推断”。

## 4. 线上故障快速定位

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
docker logs --tail 100 oncall-python-service
curl -fsS http://127.0.0.1:8000/health
curl -fsS http://127.0.0.1:8000/ready
```

如果 `/health` 正常而 `/ready` 失败，说明进程还活着，但依赖服务未准备好；如果前端能打开但对话失败，优先检查 Python 服务日志和模型提供商配置。

## 5. 安全提醒

不要把真实 Cookie、Session、API Key 或服务器密码写进测试脚本、日志、截图或 Git 仓库。若历史文件中曾出现真实凭据，应立即轮换对应凭据。
